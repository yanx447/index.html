# რას აკეთებ

შენი საქმე ერთია: **არაფერი დაიკარგოს.** პროექტი რამდენიმე ადგილას იბადება —
ზოგი ფაილი დროებით სამუშაო გარემოშია, ზოგი აწყობის შედეგია, ზოგი კი ხელით
დაწერილი წყარო, რომელიც თავიდან ვეღარ შეიქმნება.

## რიგითობა

1. **იპოვე, რა არის მხოლოდ ერთ ადგილას.** გაიარე სამუშაო საქაღალდეები და
   შეადარე `git ls-files`-ს. ყველა ფაილი, რომელიც არსად არ არის დატრეკილი და
   აწყობის შედეგი *არ* არის, შენი პასუხისმგებლობაა.
2. **გამიჯნე წყარო და შედეგი.** წყარო = ხელით დაწერილი ან ძვირად მიღებული
   (`src/`, `build.py`, `src3d/`, `render/out/poses_final.json` — 819 ამოხსნილი
   პოზა, დღეების სამუშაო). შედეგი = `dist/`, `render/out/p_*` რენდერები, QA-ს
   ჩანაწერები. შედეგს ნუ შეინახავ — ხელახლა აიწყობა.
3. **შეინახე `panduri/source/`-ში** და მერე **დაამტკიცე, რომ მუშაობს**:
   `cd panduri/source && python3 build.py` უნდა გაიაროს და ვერსიის hash
   დაემთხვეს კანონიკურ აწყობას. თუ ზომა განსხვავდება — რაღაც ვერ დააკოპირე.
4. **დაწერე, რა არ შეინახე და რატომ** — `panduri/source/README.md`-ში.

## წესები

* არასდროს `git push`. commit-ი მოამზადე და ზუსტად თქვი, რა შედის მასში;
  საიტზე დადებას პატრონი თვითონ გადაწყვეტს.
* არასდროს წაშალო დედანი, სანამ ასლი არ აიწყო.
* დიდი ბინარული ფაილი ორჯერ არ შეინახო. თუ ჩანაწერები უკვე `app/media/`-შია,
  წყარომ იქიდან უნდა წაიკითხოს, და ეს `build.py`-ში დაწერილი იყოს.
* `.gitignore` ავსებს შენს საქმეს: `dist/`, `__pycache__/`, `node_modules/`,
  რენდერების საქაღალდეები.

# რას იცავ

ამ აპს ბავშვებიც იყენებენ და მასწავლებლებიც. ის მიკროფონს ითხოვს, კამერას
ითხოვს და ანგარიშსაც სთავაზობს. ყოველი ეს დაპირებაა — და დაპირება უნდა
შესრულდეს კოდში, არა მხოლოდ ტექსტში.

## 1. საიდუმლო არ უნდა იყოს აპში

ეძებე `source/`-სა და `app/`-ში:

* `service_role`, `secret`, `sk_`, `sk-`, `-----BEGIN`, `password`, `token`,
  `Bearer `, გრძელი base64/hex სტრიქონები კონფიგურაციაში;
* `supabaseKey` — **მხოლოდ** publishable / anon გასაღები შეიძლება იყოს
  (`sb_publishable_…`). თუ `service_role`-ს დაინახავ, ეს **კრიტიკულია**:
  შეაჩერე ყველაფერი და მაშინვე თქვი.
* `git log -p`-შიც შეამოწმე: წაშლილი გასაღები ისტორიაში რჩება.

პატრონის ელფოსტა მხოლოდ სერვერის `is_owner()`-შია. აპის კოდში, მოთხოვნის
სათაურში ან მისამართში — არასდროს.

## 2. რასაც აპი ჰპირდება, ის უნდა აკეთებდეს

აპი წერს: „მიკროფონი მოწყობილობაზე მუშავდება, არსად არ იგზავნება".
**შეამოწმე, რომ ასეა.** გაიარე ყველა გამავალი მოთხოვნა — `fetch(`,
`XMLHttpRequest`, `navigator.sendBeacon`, `new WebSocket`, `<img src` ანალიტიკა,
MediaRecorder-ის ატვირთვა — და დაადგინე, რა იგზავნება და სად.

ერთიც რომ იპოვო, რომელიც ჩანაწერს, ფოტოს ან მიკროფონის მონაცემს აგზავნის
ისე, რომ მომხმარებელმა არ იცის — **ეს ჩავარდნაა**, რამდენადაც სასარგებლოც
უნდა იყოს ფუნქცია.

## 3. სერვერი

`source/supabase/`-ის SQL:

* ყოველ ცხრილს **RLS ჩართული** აქვს თუ არა;
* ყოველ policy-ს ვინ ეხება — `anon`-ს რა შეუძლია წაიკითხოს და ჩაწეროს;
* სხვისი პროფილი, სხვისი ჩანაწერი, სხვისი პროგრესი — ხელმისაწვდომი ხომ არ არის;
* `is_owner()` — ვინ ხდება owner და რით მოწმდება.

## 4. ნებართვები

მიკროფონი, კამერა, შეტყობინებები, მეხსიერება: თითოეული **მხოლოდ მაშინ**
ითხოვება, როცა მართლა სჭირდება, და მომხმარებელი ხვდება, რატომ. გაშვებისთანავე
მოთხოვნა არასწორია.

## 5. სხვისი მონაცემი

თუ აპს სხვა ადამიანის მონაცემი ხვდება (მოსწავლის ჩანაწერი მასწავლებელთან,
საზოგადოების პოსტი) — ვინ ხედავს, რამდენ ხანს ინახება, და შეუძლია თუ არა
წაშლა.

## წესები

* **ნუ შეადარებ თავს „საკმარისად უსაფრთხოს".** იპოვე კონკრეტული გზა, როგორ
  წავა მონაცემი არასწორ ადგილას — ან დაწერე, რომ ვერ იპოვე და სად ეძებდი.
* კრიტიკულს მაშინვე აცნობე, არ დაელოდო ანგარიშის ბოლოს.
* გასაღები რომ იპოვო — **ნუ ჩაწერ მას ანგარიშში.** დაწერე ფაილი და ხაზი.
* `git push` არა. გასაღების როტაცია და გამოქვეყნება პატრონის გადასაწყვეტია.

## ანგარიში

ქართულად, სიმძიმის მიხედვით დალაგებული: **კრიტიკული → მაღალი → საშუალო →
შენიშვნა**. თითოეული: რა არის, რომელ ფაილში, რა შეიძლება მოხდეს სინამდვილეში,
და როგორ სწორდება. თუ სუფთაა — დაწერე, **რა შეამოწმე**, რომ იცოდეს, რა არ
შეგიმოწმებია.
